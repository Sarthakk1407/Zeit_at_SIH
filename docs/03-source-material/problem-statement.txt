PROJECT CONTEXT
I'm building a defence-grade adaptive noise cancellation system (SIH problem
statement 26052). I need a field data-collection toolkit for a ONE-SHOT
recording session at a shooting range — I cannot return for a second visit,
so I must know at the range whether my data is usable.

Sources I'll record: air rifle, starter pistol (blank cartridge), firecrackers
of 3 sizes, balloon pops, whip crack. Plus calibration signals, room/range
impulse response sweeps, mechanical action sounds, and speech during noise.

BUILD ME A PYTHON TOOLKIT with these six tools:

1. gen_signals.py
   Generate and save playback WAVs at 96 kHz / 24-bit:
   - Log sine sweep, 20 Hz to 20 kHz, 10 s, with 0.5 s silence pad
   - Inverse filter for the sweep (save alongside, for deconvolution)
   - 1 kHz calibration tone, 30 s, at three amplitudes (-20, -12, -6 dBFS)
   - Pink noise, 30 s
   Also emit a printable one-page "playback order" sheet.

2. validate.py  ← MOST IMPORTANT, this runs at the range
   Input: one WAV file. Output: GO / NO-GO verdict plus reasons, in under
   10 seconds, printed to terminal in large readable text.
   Checks:
   - Sample rate and bit depth match expected (fail if not)
   - Clipping: % of samples at full scale, and whether clipping occurred
     during the impulse itself vs elsewhere
   - DC offset
   - Noise floor level (dBFS)
   - Wind/rumble: energy below 50 Hz relative to total — flag if excessive
   - Impulse completeness: is the transient truncated at file start/end?
   - Event SNR: peak impulse level vs surrounding background
   - Handling noise: low-frequency transients not aligned with impulses
   Print a compact table. Exit code 0 for GO, 1 for NO-GO.

3. ingest.py
   Input: one long continuous recording + a metadata CSV (schema below).
   - Auto-detect impulsive events via onset detection (energy + spectral flux)
   - Slice each event into its own WAV with configurable pre/post padding
   - Match detected events to metadata CSV rows in order, warn on count mismatch
   - Write per-event WAVs named by shot_id, plus a manifest JSON
   Metadata CSV columns: shot_id, session, tier, timestamp, recorder,
   gain_setting, sample_rate_hz, bit_depth, source_type, distance_m,
   azimuth_deg, mic_height_cm, source_height_cm, ground_surface, clipped,
   temp_c, humidity_pct, wind_kmh, wind_direction, split, notes

4. calibrate.py
   Input: calibration tone recording + the SPL meter reading I logged.
   Output: JSON with the dBFS-to-Pascal scale factor, so any later file can be
   converted to absolute pressure. Include a sanity check that flags an
   implausible scale factor.

5. ir_extract.py
   Input: sweep recording + inverse filter.
   Output: impulse response WAV, RT60 estimate per octave band, energy decay
   curve plot. Also support a balloon-pop fallback path (direct windowing,
   no deconvolution).

6. quicklook.py
   Per event: waveform, log-spectrogram, and 1/3-octave band SPL, as one PNG.
   Plus a contact-sheet PNG of all events in a session for fast eyeballing.

HARD REQUIREMENTS
- Must run fully OFFLINE on a laptop. No internet at the range.
- CPU only, no GPU. Dependencies: numpy, scipy, soundfile, matplotlib only.
  No librosa, no torch.
- Every tool is a CLI: `python validate.py recording.wav`
- validate.py must be fast and readable under stress and bad lighting —
  big text, clear GO/NO-GO, no wall of numbers.
- Handle 32-bit float WAVs as well as 24-bit int.
- Never modify input files. All outputs to a separate directory.
- Fail loudly with a clear message on malformed input, never silently.

DELIVERABLES
- The six scripts
- requirements.txt with pinned versions
- README.md with a range-day quickstart: exact commands in the order I'll
  run them
- A make_test_data.py that synthesises fake impulse recordings (including
  deliberately clipped, wind-contaminated, and truncated cases) so I can
  verify every tool works BEFORE the range day

ACCEPTANCE CRITERIA
- make_test_data.py produces the bad cases, and validate.py correctly
  returns NO-GO for each with the right reason
- Full pipeline runs end to end on the synthetic test data
- validate.py completes in under 10 s on a 60-second 96 kHz file
